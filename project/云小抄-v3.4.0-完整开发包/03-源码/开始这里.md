## 三条路，挑一条

### 路 A：Windows 双击一下（最快）

1. 装 **JDK 17**：<https://adoptium.net/temurin/releases/?version=17>
   → 选 Windows x64 JDK 17 → `.msi` → 安装时**勾上 `Set JAVA_HOME variable`**
2. 装 **Android Studio**：<https://developer.android.com/studio>
   → 首次启动选 Standard → 进主界面后到 SDK Manager 勾上：
   - SDK Platforms：`Android 16.0 (API 36)`
   - SDK Tools：`Show Package Details` → `Build-Tools 36.0.0`
3. 把这个文件夹解压到 **`D:\dev\yunx-guide`**（纯英文、无空格、路径短）
4. **双击 `一键打包.bat`**

它会自己检查环境、写 `local.properties`、编译、把 APK 复制成
`云小抄-v2.5.3-debug.apk` 并帮你打开所在文件夹。

> 报错的话，把最后 30 行（`e:` 开头和 `FAILURE:` 之后那段）贴给我，我改代码。

## 这个版本改了什么（v2.5.1 → v2.5.3）

### 1. 液态玻璃改成 iOS 那种

| | 旧 | 新 |
|---|---|---|
| 填充 | 深色 10% / 2.7% 白 | 8% / 2% |
| 描边 | 线性渐变 85%/12% | **三段** 92% → 42%高度降到 24% → 6% |
| 顶部受光 | 14% 白，铺到 30% 高度 | 10% 白，只铺 18% |
| 斜向镜面 | 10% 白（浅色 34%） | 4.5%（浅色 14%） |
| 内侧反光 | **7dp 宽，深色用白 8.5%** | **3dp，两套统一用黑 6%** |
| 彩虹色散 | 30%，所有档位 | 9%，仅「极致」档 |
| 顶部亮线 | 1.5dp | 1.1dp |

其中「内侧反光深色用白」是**写反了**——玻璃内缘应该是暗的（厚度把光挡在边缘里），
深色底上给白等于在刚提亮的上沿里面又叠一道灰箍，圆角处还堆成脏灰。这是「不像苹果」
最明显的一处。

改的文件：`ui/UiStyle.kt`、`ui/FrostedGlass.kt`。**调用点零改动。**

### 2. 修了「点按钮有时候卡死」

真凶在 `ui/StyleCurtain.kt` 的 `switch()`：

```kotlin
GuideStyleStore.select(context, style)
withFrameNanos { }        // ← 等新皮肤那一帧
anim.animateTo(1f, ...)
```

`withFrameNanos` 靠 `AndroidUiDispatcher` 的帧时钟回调，**窗口不可见时不回调**。
而点「切换风格」这个动作，恰恰是「外观弹窗 `onDismiss()` + 遮罩全合 `progress = 0`」
的同一瞬间。帧时钟不回调 → 协程永久挂住 → 遮罩停在 0 → **整屏盖死，只能杀进程**。

修法三层：`withTimeoutOrNull(150)` 包住等帧、独立看门狗（`cover+reveal+700ms`
后强行揭盖）、`catch` 里区分 `CancellationException`。

另外给开屏闸门加了墙钟兜底：`MainActivity` 只把 `gate` 关掉，开门全靠
`SplashOverlay.onExitStart`；`TileEntrance` 在闸门关时所有模块 alpha=0，遮罩又全屏
吃触摸 → 回调不来就是「空白 + 点不动」。现在视频 `MAX_VIDEO_MS+2500`、
图片 `holdMs+2500` 到点强制开门。

`ui/TileEntrance.kt` 里入场时钟也加固了：`factor ≤ 0` 时原来 `ms` 恒为 0，
`while(true)` 永不退出且每帧写 state —— 真锁死。

### 3. Gradle 9.0.0 → 8.14.3

9.x 对 AGP 8.13 属于前沿组合，8.14.3 是 8.x 最后一个稳定系列里验证最充分的补丁版。

**AGP 8.13.0 / Kotlin 2.1.0 / KSP 2.1.0-1.0.29 故意没动**：`compileSdk = 36`
要求 AGP ≥ 8.9；KSP 版本号是 `<Kotlin版本>-<KSP版本>` 锁死的；Compose 插件跟
Kotlin 走。降它们只会引新问题。

## 关于「重复下载 Bug」

查过了，**这份代码里没有「重复下载」这个问题，也不需要改**。

真实实现（`data/SyncPlan.kt` 的 `decide()`、`data/ImageVault.kt` 的 `verdict()` /
`key()`）用的是：

- key = `platform:id`
- 比对 = `originSize` + `md5`

比「相对路径 + 文件大小 + 修改时间」更严格 —— 修改时间会被解压/拷贝改掉，
按它比对会导致整批误判重下。

另外 `ImageVault.find()` 已经处理了「索引里有但物理文件被删」的情况：删掉索引条目，
判定为 NEW 重新下载。

如果你遇到的具体症状是「点两次一键下载会下两遍」，那是另一个问题（并发重入），
把症状告诉我，我按代码定位。
